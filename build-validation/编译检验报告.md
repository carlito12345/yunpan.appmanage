# 公签版 APK 编译检验报告

## 结论

主包和内嵌模块的 smali 均已强制重新编译成功。交付 APK 使用主包新生成的三个 DEX，并保留原 APK 的资源、清单及其他载荷，已使用提供的 platform 密钥和证书签名。

Java 导出工程未通过编译。对 12,072 个 Java 文件运行 javac 后，编译器报告 2,593 条错误，日志列出前 100 条详细诊断。例如 `a1/d.java:402` 含有反编译器生成的 `?? r11`。这些诊断可能包含连带错误；修复语法后仍可能出现依赖或类型错误。本次不是从 Java 源码成功构建 Android Gradle 工程，不能将结果描述为已恢复原始可编译源码。

本次完成编译与静态一致性检验，未安装 APK，未验证实机运行行为。

## 两类回编译差异及处理

DEX 比较使用相同的 baksmali 输出方式，比较字段、方法、指令、寄存器、引用和异常处理结构，不比较调试信息。其中 19 个类仅存在显式默认静态字段值被省略的差异；1 个类存在相邻同处理器 try 区间合并，额外比较了指令文本与合并后的异常覆盖范围，结果一致。其余类的规范化文本一致。清单见 `dex-representation-differences.txt` 和 `dex-equivalent-try-layouts.txt`。

资源全量回编译虽然成功，但检测到 34 个内部 drawable 资源 ID 的分配发生变化，详见 `resource-roundtrip-differences.json`。因此没有把这个全量回编译产物作为交付版。最终打包从原 APK 保留全部非 DEX 载荷，移除旧签名，仅替换三个已验证的回编译 DEX，然后重新对齐与签名。最终交付包的清单、资源表及原始资源内容均保持原样。
