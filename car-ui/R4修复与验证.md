# R4 子页面适配修复

R4 针对新增的悬浮按钮橙色大块及其他子页面的共用布局缺口。它是公签测试版，不能沿用 R3 的局部 VM 结果作为 R4 的安装验收。

## 已改动的布局合同

- **悬浮按钮、侧边手势、自定义映射**：顶部功能条、开启开关/图标、触发区域/方式、映射动作和完整说明分别安排。保留原列表、选择和回调；旧装饰分隔节点保留身份并退出内容测量。
- **选择条与主体**：短功能/类别条有独立高度，沉浸、权限、通用/日志映射、进程内存等页面的主列表获得剩余空间。
- **操作栏与主体**：完整的返回/添加/清空等原动作按宽度换行，保留已有水平表格结构，不再根据文本长度把所有横排容器改成竖排。
- **滚动表单与固定底栏**：原 ScrollView/NestedScrollView 保留为有界 viewport；原固定高局部列表、预览图和 spacer 保留尺寸。表单标签按新列结构左对齐，底部备注与返回/确认可以在同一操作栏排列。
- **多内容区和文件选择**：下载页分文件浏览与链接/任务，随可用宽度上下或左右安排；二维码、历史、帮助和加载保留原显隐关系。文件选择和固定底栏表单对话框按所属窗口测量。
- **自然高度设置控件**：内容高度与真正弹性区域分开，薄线保持薄尺寸；原本隐藏的内容包装层随原 View 显隐，避免抢占可见区域的空间。

长说明独立于短版本页脚，完整显示，不再统一限制为两行。侧边设置的原手势预览区域保留。代码编辑器保留原根宿主及直接上下锚点，仅明确工具条高度；没有声称真实编辑器已运行验收。

## 验证来源与范围

最终测试结果和时间见 `build/gradle-test-r4-final.log`、`build/test-results/test/`。R4 回归使用原 APK 的二进制 XML 和原行资源，填充明确的测试数据；没有运行所有原业务控制器。动态编辑器宿主的锚点测试用 SurfaceView，不能代表真实编辑器行为。R3 的原绑定方法测试及 Hive 静态测量/绘制来源保持原边界。

`previews/regressions-r4/` 是原生图形测试捕获，覆盖三类映射的三主题和双方向、浮钮外观、带底栏的表单/文件选择实际 Window 尺寸，以及一个 1.3 字号表单。文件选择捕获显式使用已填充状态，未把同时存在的默认错误/加载占位当成运行状态。旧 `-1640.png` 中间捕获不进入交付包。

库存仍登记 333 个应用布局，其中 326 个通过载入、原控件/ID 保留与测量烟测，7 个特殊控件布局未在 JVM 执行，详见 `模块检查记录-R4.md`。这些计数不表示 333 页已逐一重写、视觉检查或业务验收。其他未执行的原模块、真实网络/安装/权限/服务、车辆硬件和完整生命周期仍未验证。

## VM 状态

R3 在 `192.168.1.18:10000` 的 Android 11 VM 曾通过部分路径检查，随后在同一 VM 确实复现新增的悬浮按钮失败，见 `build/vm-validation/r3-float-before.png`。此前 F1–F6 的局部通过没有覆盖这条路径，也不代表其他页面都已优化。

尝试覆盖安装 R4 时 ADB 返回 `device offline`；重新连接超时（10060），随后设备不再列出。因此 R4 尚未成功安装、没有新的 VM 运行截图。需恢复 VM/ADB 或提供新地址后继续安装、复拍这次新增页面及原有回归路径。此状态是实际连接失败，不是审批或权限确认。

应用搜索的名称/包名结果直接合并而产生重复项，仍是独立未修业务问题。

## 构建身份

APK 为 `应用管家-全面适配测试-R4-20261104.apk`。当前准确 SHA-256、签名与资源保留信息见 `build/package-verification.json`。使用用户提供的同一公签证书，检查 v1/v2/v3 签名和 ZIP 对齐；原业务资源、原生库、第二/第三 DEX 与内嵌 APK 保持字节一致。原 Java 全工程仍不能直接构建，本次 UI 扩展源码可以独立编译。公钥证书随包交付，私钥不进入源码 ZIP。
